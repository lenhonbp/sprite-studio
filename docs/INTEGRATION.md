## Move between live edits and production QA

1. Read current studio revision and export to a new source path. Record that revision with the candidate; do not treat the asset ID as a revision.
2. Author a fresh candidate using rig CLI. Render to a new directory. Preserve original raster sources; never mark the sample demo production approved.
3. Run the full skill's validate/inspect/preview/motion-check. Bind current evidence with review-template, inspect it and complete observations before qa. Mathematical socket locations need actual visual checking against grip/art.
4. Import the candidate into the live editor with the **revision recorded before authoring**. If 409, compare current project and reconcile; do not simply reread and overwrite the new project. The import is an authoring update, not art acceptance.
5. Keep Technical → Visual → Runtime acceptance separate. Rig render/sheet exports and editor frame ZIPs are candidates. Approved production atlas release still requires the full skill's current review and actual target-engine tests.

Example commands from repository root (choose new output paths):

```sh
npm run studio -- read
npm run studio -- export projects/source-01.rig.json
npm run rig -- set-key projects/source-01.rig.json --clip attack_se --bone arm_front --time 300 --values '{"rotation":-45,"easing":"smooth"}' --out projects/candidate-01.rig.json
npm run rig -- render projects/candidate-01.rig.json --fps 12 --out candidates/hero-01
npm run art -- inspect candidates/hero-01/animation-set.json --out candidates/inspect-01.json
npm run art -- preview candidates/hero-01/animation-set.json --out candidates/preview-01
```

These are candidate preparation steps only. Shell quoting differs in Windows; use the skill's command help for platform-specific invocation. JSON import uses studio import with explicit --revision as described in docs/LOCAL.md.

## Git and installation

ZIP contains the repository source, not a Git history/remote or runtime .studio state. Initialize your Git repository and commit it after review; no original Site or personal-skill remote is attached. .gitignore excludes local state, credentials, native dependencies and generated proof caches. Explicitly exported project source can be versioned at your discretion.

An agent can apply the bundled skill by reading AGENTS.md without installing it globally. To install as a skill on another host, select/copy the complete skills/produce-game-sprites directory using that host's supported workflow. Avoid duplicate personal installs under different names. MCP configuration remains a separate host action; cloning does not automatically enable MCP or make remote localhost accessible on your phone.

The cloud Site manifest belongs to the original deployment and is optional for local use. Do not publish it to a different account without setting up your own Site configuration. This handoff does not change the hosted Site or its audience.
